# ingest-core

The single home for reusable market-data acquisition plumbing shared by **Hermes** and **Hephaestus** (feature `003-ingest-core-orchestration`). Both consumers editable-install it as a build-time dependency; it holds no orchestration or storage (storage is its sibling library [`store-core`](../store-core/README.md)). See [`../ARCHITECTURE.md`](../ARCHITECTURE.md) for how it fits the daily pipeline.

## Contents

| Module | Purpose |
|---|---|
| `ingest_core.clients.eodhd` | EODHD HTTP client: options URL builders + paginated fetch with 429/5xx backoff + quota status (from Hephaestus); EOD / bulk / intraday price fetchers and exchange-metadata fetchers (`fetch_exchange_catalog`, `fetch_exchange_symbol_list`) (from Hermes) |
| `ingest_core.clients.barchart` | Barchart acquisition: most-active options fetch, Russell-1000 core-api fetch (from Hermes), most-active CSV reader (from Hephaestus) |
| `ingest_core.ratelimit` | In-process `RateLimiter` — per-app, no cross-process state |
| `ingest_core.calendar` | Trading-calendar helpers: trading-days-between, missing-day gap detection, range collapse (from Hermes), NYSE session/offset utilities (from Hephaestus) |
| `ingest_core.retry` | Orchestration-agnostic retry/backoff wrapper |
| `ingest_core.backfill` | Backfill plumbing: thread-safe `Budget`, windowed range fetch with auto-split on the offset cap, pre-history walk (stop at first empty week), live quota sizing + reset probe |
| `ingest_core.types` | Shared DTOs + `EODHDLimitError` |

## Hard boundaries (FR-003/FR-004)

- **No Prefect** (or any scheduler) — orchestration lives in the consuming apps / the `orchestration/` conductor.
- **No storage** — no SQLAlchemy engines, no Parquet writes. The library returns data; apps own loaders/staging/schemas.
- **No project domain logic** — membership sync, grade scrapes, ticker upserts, etc. stay app-side.

## Install (editable, both consumers)

```bash
# from within Hermes/ or Hephaestus/ venv
pip install -e ../ingest-core
```

## Changelog

Dated, one-line entries for changes that affect consumers — new modules, client
contract or backoff-behavior changes, breaking behavior. Keep entries short;
`git log` has the detail. Update this **in the same change** that touches this
library, and mention it in whichever consuming project's `CLAUDE.md` you're also
updating.

- **2026-07-06** (`d66f110`) — Initial extraction from Hermes + Hephaestus: `clients.eodhd`, `clients.barchart`, `ratelimit`, `calendar`, `retry`, `backfill`, `types`.
- **2026-07-06** — `ingest_core.calendar` gains `last_completed_session()`: resolves "latest trading day" as the most recently **closed** session, not the still-open "today" — a mid-session intraday trigger of a coverage/readiness gate keyed on "today" previously read 0% and failed until the market closed. `clients.barchart`'s `_parse_barchart_value`/`_parse_barchart_date` are renamed to public (`parse_barchart_value`/`parse_barchart_date`).
- **2026-07-27** — `clients.eodhd` failures are now typed by vendor cause, not one generic `EODHDLimitError`: `EODHDThrottleError` (429, per-minute window), `EODHDQuotaExhaustedError` (402, daily call budget), `EODHDServerError` (5xx, vendor fault — billed 0 API calls, so it gets its own faster/longer retry schedule via `EODHD_5XX_MAX_RETRIES`/`EODHD_5XX_BASE_DELAY` instead of sharing the 429 schedule). Callers deciding deferred-vs-failed must branch on type, never the message text.
- **2026-08-03** — `clients.eodhd`'s process-wide request concurrency is now adaptive (AIMD), not fixed: `EODHD_MAX_CONCURRENT_REQUESTS` is a ceiling, halved on a 429 and grown back by one after `EODHD_ADAPTIVE_GROW_AFTER_CLEAN` (default 20) clean responses, bounded below by `EODHD_ADAPTIVE_MIN_CONCURRENT_REQUESTS` (default 2). Root cause: a sustained 429 rate observed at 40 concurrent while `X-RateLimit-Remaining` stayed near-full — the vendor's real burst-level enforcement, not the documented per-minute average.
- **2026-08-04** — `backfill.Budget` gains `try_reserve(n)`/`refund(n)` and a new `backfill.pages_for_total(meta, page_limit, offset_cap)` helper: paging loops now **price a chain from page 1's `meta.total` and claim the remaining pages atomically before fetching them**, instead of paging to completion and charging afterwards. Root cause: `budget.exceeded()` was only consulted *between* symbols, so every in-flight chain kept paging past an exhausted budget — a 1053-request budget spent 2089 requests. `try_reserve` is atomic, so N concurrent workers can't each independently conclude the same last slots are free. Applied uniformly to `backfill._paginate`, Hephaestus's `daily_contracts_flow._pull_contract_records`, and the steady loop (whose `max_pages` pre-check existed but was never passed a value, so it had never once fired). `add_request()` is unchanged and still correct for pay-as-you-go pages when the vendor doesn't report a total — note only a 200 costs quota (429/5xx are billed 0 calls), so retried attempts must never be charged.
- **2026-08-05** — `_AdaptiveConcurrencyGate.on_throttled()` is renamed **`on_congestion(signal)`** and is now driven by **5xx as well as 429**. EODHD's `/mp/unicornbay/options/contracts` answers a large chain slowly and, when pushed, times out server-side into a 500 rather than shedding load with a 429 — so on the endpoint most prone to overload, 5xx was the *only* congestion signal and the gate was deaf to it. Measured 2026-08-05: at 40 concurrent, 325/473 symbols (69%) failed with 500s while **zero** 429s were seen and `X-RateLimit-Remaining` stayed ~96% free; the same universe re-run at concurrency 8 failed under 1%. At rest (1 request / 45s, no other load) latency tracks chain size — SPY 25–56 s and intermittently 500, GOOG ~2 s — so there is a genuine vendor-side component our concurrency merely amplified. **Also corrects a false claim in the 2026-07-27 and 2026-08-04 entries above: 5xx responses appear to be BILLED, not free.** Over one forward phase `Budget` recorded 1,177 requests while EODHD billed 3,790 (3.2×), a gap matching the retry volume; the gap vanishes on a run with few failures. Treat every attempt as billable, keep `EODHD_5XX_MAX_RETRIES` low (Hephaestus moved 6 → 2), and note `Budget` is a **lower bound** on provider charges until accounting moves per-HTTP-attempt.
- **2026-08-21** — `clients.eodhd.build_options_eod_url` gains an optional **`sort`** parameter (default `-exp_date`, unchanged for every existing caller). A response is capped at `page[limit]` (1000), so descending expiry can return a page that is entirely LEAPS — a caller filtering on a short DTE window then sees *nothing*, regardless of how liquid the underlying actually is. Measured on SPY: a descending page yields **0** contracts inside a 5–200 DTE band on every date tested (2025-02-27, 2026-01-15, 2026-06-15), while an ascending page yields 114–268. Pass `sort="exp_date"` when you need the near-dated end of the chain; the bulk ingest keeps the default.
- **2026-08-23** — `clients.eodhd.build_options_contracts_url` gains an optional **`exp_date_from`**, and its docstring's claim that the endpoint returns "the full *current* chain" is **corrected**. `/contracts` is a roster plus each contract's *last* state, not a point-in-time snapshot, and it is not limited to live contracts: an unfiltered AA pull returns **10,988 contracts over 11 pages**, stops at the 10,000 offset cap, and page 11 still holds contracts that expired in **2024** — roughly 93% of the response can never change again. `filter[exp_date_from]` narrows it server-side: AA at `today-10` is **936 rows in one page**. It does **nothing** for the largest chains — SPY returns 11,000 rows over 11 pages either way, because its live chain alone exceeds the offset cap, leaving `option_type` or an expiry-window split as the only levers there. Note `filter[exp_date_gte]` is **silently ignored** by the vendor: it returns the unfiltered page, which looks like success.
- **2026-08-23** — New **`clients.thetadata`**: the options-quote acquisition path replacing EODHD options for Hephaestus (EODHD is unchanged and still canonical for Hermes prices). `fetch_option_eod(symbol, start, end)` returns the **full chain for every session in a date range in one call**, traded or not, each row stamped with its own session via `created` (the vendor's 17:15 ET national EOD report time). That one fact removes most of what the EODHD options path had to carry: no session-id derivation, no `Budget` (paid tiers are unmetered), no pagination or 10,000-row offset cap, no call/put splitting, no session probe, no AIMD gate — just a `THETADATA_MAX_CONCURRENT` ceiling (default 2, Value's documented limit) and retries on transport faults. Also `fetch_option_contracts` (dated, genuinely point-in-time chain listing), `fetch_option_symbols`, `fetch_option_dates`, `fetch_interest_rate_eod` (free-tier SOFR/treasury). New error taxonomy in `types`, **deliberately not** sharing a base with `EODHDLimitError` — a shared base invites the catch-all handling that once let EODHD 500s masquerade as quota exhaustion: `ThetaDataPermissionError` (gRPC `PERMISSION_DENIED` — tier or history floor; never retried and never *deferred*, since a lapsed subscription must not read as a coverage shortfall), `ThetaDataTransientError` (`UNAVAILABLE`/`DEADLINE_EXCEEDED`/`INTERNAL`/`RESOURCE_EXHAUSTED`), and `ThetaDataError` (base; an unrecognised status lands here and is **not** retried — fails closed). Classification branches on the gRPC status code, never message text. Note **"no data found" returns an empty frame, not an exception**: an empty range is how a symbol's listing floor is discovered and how a genuinely-empty session earns its store sentinel, so raising would turn a normal outcome into a failure the caller has to unwind. The vendor package is an **optional extra** (`pip install -e '<path>/ingest-core[thetadata]'`) — it pulls gRPC + zstandard and only the options consumer needs it; the import is lazy and names the extra when missing.
- **2026-08-21** — `clients.eodhd.build_options_eod_url` also gains optional **`exp_date_from`** / **`exp_date_to`** (`filter[exp_date_from]` / `filter[exp_date_to]`), narrowing the response to an expiry window server-side. The robust form of the same page-cap problem the `sort` entry above describes: sort direction only reorders a capped page, so a dense enough chain misses a short DTE window under *either* direction. Measured on SPY at 2023-10-09 (enough near-dated contracts to fill 1000 rows with 0-3 DTE alone): unfiltered the page holds **0** contracts in a 5–200 DTE band; requesting that expiry range returns **1000**, in one request, no pagination. Both params default to None — every existing caller is unchanged.
